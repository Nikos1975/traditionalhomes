# ICM Auxiliary Capability Selection

Use this reference only when deciding whether to load, create, install, retain, or require another skill or auxiliary capability.

## Admission test

Admit an auxiliary capability only when all of these are true:

- it directly solves a problem required by the current task;
- equivalent guidance is not already active;
- it materially improves correctness, safety, or execution; and
- its context and maintenance cost is justified.

Availability, popularity, possible future usefulness, or conventional bundling is not sufficient.

## Lowest reliable layer

Prefer, in order:

1. the active project procedure when it already governs the work;
2. a deterministic script or test for mechanical, repeatable, testable work;
3. a stable rule, reference, or template for persistent workflow logic; and
4. a reusable skill when the recurring value is how to perform the work rather than project-specific facts, credentials, approval state, or current priorities.

## Runtime independence

Meta-skills must not override the project's canonical routing map or force mandatory skill chains. ICM must remain functional when optional auxiliary skill frameworks are absent.
